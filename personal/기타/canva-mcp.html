1. 작동 방식

Canva MCP는 로컬에 설치하는 프로그램이 아니라 Canva가 운영하는 원격 서버다. Claude Code는 https://mcp.canva.com/mcp 로 JSON-RPC 요청을 보내고, 실제 디자인 조작은 전부 Canva 쪽에서 일어난다.

① 클라이언트Claude Code 어떤 도구를 어떤 인자로 부를지 결정
② 전송HTTP + OAuth 2.1 토큰은 내 PC에만 저장, 브라우저로 최초 1회 승인
③ 서버Canva 디자인 생성·편집·렌더링을 직접 수행
④ 응답JSON + 썸네일 디자인 ID·URL·미리보기가 대화로 돌아옴

그래서 클로드 데스크탑과 CLI의 기능 차이는 없다. 서버·프로토콜·권한이 동일하기 때문이다. 차이가 있다면 커넥션을 누가 들고 있고 토큰을 어디에 저장하느냐 정도이고, CLI는 OAuth 콜백을 로컬 포트로 받으므로 브라우저를 띄울 수 없는 원격 SSH 환경에서만 인증이 곤란해진다.

중요 — 파일이 오가지 않는다. 내 PC의 이미지·PDF를 Canva로 밀어 넣는 경로는 기본적으로 없고, Canva가 접근 가능한 공개 HTTPS URL만 받는다. 이 제약이 뒤의 여러 한계를 만든다.

2. 연결하기

claude mcp add canva --transport http https://mcp.canva.com/mcp

등록 후 세션 안에서 /mcp → canva → Authenticate. 브라우저가 열리면 Canva 계정으로 승인하면 끝이다.

등록 범위(scope) 고르기

scope저장 위치적용 범위공유
local (기본)~/.claude.json 의 프로젝트 경로 키이 폴더에서만안 됨
user~/.claude.json 전역모든 폴더에서안 됨
project프로젝트 루트의 .mcp.json이 저장소를 여는 모두Git 커밋됨

여기서 "프로젝트"는 claude를 실행한 디렉터리 하나를 뜻한다(절대 경로가 그대로 키가 된다). 폴더를 옮겨 다니며 쓸 거면 -s user로 등록하는 편이 낫다. 이름이 겹칠 때 우선순위는 local > project > user. 토큰은 scope와 무관하게 로컬에 따로 저장되므로 로그인은 한 번이면 된다. 

claude mcp add canva -s user --transport http https://mcp.canva.com/mcp   # 전역
claude mcp get canva      # 상태 확인
claude mcp remove canva -s local   # 해제

4. 실전 워크플로

① 새 프레젠테이션 만들기

1요청"~ 주제로 5장짜리 발표자료"
2후보 생성여러 시안이 썸네일로 제시됨
3선택고른 것만 내 계정에 확정
4다듬기 → 내보내기텍스트 수정 후 PDF/PPTX
장수는 적게 시작하는 게 좋다. 슬라이드가 늘어날수록 생성 시간이 가파르게 늘어난다(15장이면 5장의 3배 수준). 기본값은 1~5장이고, 명시적으로 요청해야 balanced(5~15장)·comprehensive(15장 이상)로 간다.
만드는 종류는 프레젠테이션 말고도 26가지가 있다 — 문서(Canva Doc), 리포트, 제안서, 포스터, 전단, 인포그래픽, 명함, 로고, 이력서, 초대장, 인스타/페북/X 게시물, 유튜브 썸네일·배너, 스토리, 배경화면 등.

② 이미 있는 디자인 고치기

제목 변경, 오탈자 수정, 번역, 텍스트·이미지 교체, 서식 변경이 모두 여기 해당한다. 반드시 트랜잭션 3단계를 거친다. 

디자인 찾기 → 트랜잭션 시작 → 편집 조작(여러 개 한꺼번에) → 커밋
커밋하지 않으면 전부 사라진다. 편집 결과는 커밋 전까지 초안 상태로만 존재한다. 반대로 말하면 마음껏 시켜봐도 안전하다 — 마음에 안 들면 취소하면 원본은 그대로다.

가능한 조작:

  • 제목 변경, 텍스트 통째 교체, 특정 문자열만 찾아 바꾸기
  • 이미지·영상 교체 및 새로 삽입(위치·크기·회전·투명도 지정 가능), 요소 삭제
  • 요소 이동·크기 조정
  • 서식: 색상, 크기, 굵기, 기울임, 밑줄, 취소선, 정렬, 줄간격, 링크, 글머리표/번호 목록
  • 브랜드 템플릿의 자동채움 필드 연결·해제

③ 내가 만든 파일을 Canva로 가져오기

직접 만든 HTML 슬라이드나 PDF를 Canva에서 마저 다듬고 싶을 때 쓴다. 공개 HTTPS URL이면 그대로 가져온다. 이 사이트(GitHub Pages)에 올려둔 파일이나 GitHub raw 링크가 바로 그 조건을 만족한다.

HTML을 페이지로 쪼개려면 슬라이드가 될 요소마다 data-document-role="page" 속성을 붙인다. 페이지끼리 중첩되면 안 된다. data-label로 페이지 제목, data-speaker-notes로 발표자 노트도 같이 넘길 수 있다. 속성을 안 붙이고 그냥 넣으면 웹사이트/앱 같은 인터랙티브 디자인으로 해석된다.

5. 한계와 주의점

로컬 파일은 못 올린다. C:\..., file:// 경로는 받지 않는다. 이걸 우회하려고 개인 파일을 임시 공유 사이트에 올리는 건 하지 말 것 — 되돌릴 수 없이 인터넷에 공개된다. Canva 웹에서 직접 업로드하고, MCP로는 그 다음부터 다루는 게 맞다.
  • 글꼴(font family)은 바꿀 수 없다. 크기·굵기·스타일은 되지만 서체 자체 교체는 지원하지 않는다. 한국어 자료라면 생성 단계에서 서체가 정해지고, 이후엔 Canva 에디터에서 손대야 한다.
  • 반응형 페이지는 조작이 제한된다. Canva Doc처럼 유동 레이아웃인 페이지에서는 제목 변경·텍스트 교체·찾아 바꾸기·이미지 교체·요소 삭제만 되고, 위치/크기 조정 같은 건 통하지 않는다.
  • 정밀 레이아웃 설계용 도구가 아니다. 빈 캔버스에 도형을 그리거나 새 텍스트 상자를 만들어 배치하는 조작은 없다. 구조는 생성·템플릿이 잡고, MCP는 그 안의 내용을 갈아끼우는 쪽에 강하다.
  • 내보내기 형식은 먼저 확인해야 한다. 디자인마다 지원 형식이 달라서, PPTX나 MP4가 항상 되는 건 아니다.
  • 디자인 검색의 종류 필터는 현재 프레젠테이션만 지원한다. 다른 종류는 제목·내용 검색으로 찾아야 한다.
  • Canva 계정의 요금제를 그대로 따른다. 프로 전용 소재나 고품질 내보내기는 계정 권한이 없으면 막힌다.

수식·특수문자·옛한글 표기가 정확해야 하는 자료👎 서체 통제가 안 돼 깨질 위험

요약하면 "보기 좋게"가 목적이면 Canva, "정확하게"가 목적이면 직접 HTML. 둘을 섞을 수도 있다 — 초안을 Canva로 뽑고 세부는 에디터에서 손보거나, 반대로 HTML로 정확히 만든 뒤 가져와 디자인만 입히는 식이다.
