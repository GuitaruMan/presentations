# 수업자료 제작 작업지침

국어 수업용 프레젠테이션(HTML 슬라이드 덱)을 만들 때 따르는 기준을 정리한 문서다.
다른 컴퓨터에서 같은 작업을 시작할 때 이 파일 하나만 읽으면 되도록 썼다.

- 게시 위치: `github.com/GuitaruMan/presentations`
- 최종 수정: 2026-08-19

---

## 0. 다른 컴퓨터에서 시작하는 법

```bash
git clone https://github.com/GuitaruMan/presentations.git
cd presentations
python -m http.server 8000     # file:// 로는 열리지 않는다. 반드시 서버로 확인
```

## 2. 원자료와 읽는 법

이 컴퓨터 기준 원본 위치는 `C:\ForClaude\ForTeaching\` 이다.

| 파일 | 내용 | 읽는 방법 |
|---|---|---|
| `수능완성 - N강.pdf` | 실전 모의고사 N회 지문·문항 | **이미지 PDF다.** 텍스트 추출이 안 되므로 `pdf_render_pages`에 `clip`을 주어 한 단(段)씩 잘라 읽는다 |
| `수능완성 답지.pdf` | 전 회차 정답과 해설 | 텍스트가 추출된다. `pdf_search`로 지문 키워드를 찾아 해당 페이지를 `pdf_read_all`로 읽는다 |

### 이미지 PDF를 읽는 요령

교재는 2단 조판이라 페이지 전체를 한 번에 렌더링하면 글자가 뭉개진다.
한 페이지를 네 조각(좌상·좌하·우상·우하)으로 잘라 200dpi로 읽는다.

```
pdf_render_pages(path, pages="3", dpi=200, clip=[0.02, 0.05, 0.50, 0.58])   # 좌단 위
pdf_render_pages(path, pages="3", dpi=200, clip=[0.02, 0.55, 0.50, 1.00])   # 좌단 아래
pdf_render_pages(path, pages="3", dpi=200, clip=[0.48, 0.05, 0.96, 0.58])   # 우단 위
pdf_render_pages(path, pages="3", dpi=200, clip=[0.48, 0.55, 0.96, 1.00])   # 우단 아래
```

`clip`을 준 렌더링은 축소되지 않으므로 이 방법이라야 본문이 또렷하다.

### 답지에서 정답 찾기

`실전 모의고사 N회` 해설 첫 페이지에 **전 문항 정답표**가 한 덩어리로 실려 있다.
그 페이지를 먼저 읽어 정답을 확보하고, 이어지는 페이지에서 문항별 해설을 읽는다.

## 3. 두 계열의 덱

골격과 색이 서로 다르다. 섞지 않는다.

### (가) 고전시가·고전소설 계열
- 기준 파일 `work/수업/가시리_1학년_1차시.html`
- 파일명 `<작품>_<학년>_<차시>.html`
- 작품마다 CSS 변수로 강조색을 바꾼다 (가시리=단청 붉은색 `#a8322a`, 묏버들=버들 초록 `#3f7048`, 개여울=물빛 `#2f6b8f`)
- 옛한글은 첫가끝 조합형 **숫자 문자 참조**로 적는다
  (`ᄒᆡ`=`&#4370;&#4513;`, `ᄃᆡ`=`&#4355;&#4513;`, `ᄂᆞᆫ`=`&#4354;&#4510;&#4523;`)
- 원문은 위키문헌 등으로 **반드시 대조 검증**한다. 다른 차시 작품을 인용할 때는
  그 차시 HTML의 표기를 **그대로 복사**한다(새로 타이핑하면 음보 끊기가 틀어진다)
- 배치 순서는 **내용 → 표현 방식 → 형식**. 번갈아 배치하지 않는다
- 음수율(7·5조 등)은 쓰지 않는다. **음보율로만** 설명한다(한시는 예외)

### (나) 수능 독서(비문학) 계열
- 기준 파일 `work/수업/수능국어_1회_1-3번.html`
- 파일명 `수능국어_<회차>회_<문항범위>번.html` (예: `수능국어_3회_10-13번.html`)
- 색: 파랑 `--key #1f5fbf` / 빨강 `--warn #c2372d` / 초록 `--ok #1d7a55`
- **지문 하나당 파일 하나.** 한 회차에 독서 지문이 넷이면 파일도 넷이다

아래 4~7장은 (나) 계열을 기준으로 쓴다. (가) 계열도 문체 규칙(5장)은 똑같이 적용된다.

## 4. 슬라이드 구성

```
1  표지
2  지문 구조 한눈에 보기        문단별 요지를 번호와 함께 나열
3~ 개념 정리 2~4장             지문의 핵심 개념·대립 구도·인과 사슬
   (문항마다)
   ─ 문제 슬라이드             선택지 원문 + 정답 표시
   ─ 정답과 근거               정답 배너 + 지문 근거 2칸 + 보충 한 상자
   ─ 선택지별 확인 (필요시)     오답이 많이 나온 문항만
```

- **마무리 정리 슬라이드("오늘 가져갈 것" 등)는 만들지 않는다.** 기준 파일에 없는 형식이다.
- `<보기>`가 길면 `<보기>` 한 장 + 선택지 한 장으로 나눈다. 억지로 한 장에 넣지 않는다.
- `.page-num`과 하단 `#counter`의 총 장수를 실제 슬라이드 수와 맞춘다.
- 분량 기준: **지문 하나당 13~20장**. 그보다 길어지면 내용을 덜어낸다.

### 문제 슬라이드에 정답 표시

학생은 **다 풀고 나서** 강의를 듣기 때문에 문제 슬라이드에 정답을 함께 띄운다.

```html
<h2 class="slide-title">
  <span class="q">01</span>
  <span class="qtext">윗글을 이해한 내용으로 적절하지 <u>않은</u> 것은?</span>
  <span class="ans-chip">정답 ④</span>
</h2>
...
<li class="ans"><span class="n">④</span><span class="txt">…</span></li>
```

정답 칩(제목 우측)과 정답 선택지 강조(`li.ans`) 두 가지를 함께 쓴다.

### 해설 슬라이드의 3층 구조

```html
<div class="ans-banner">   <!-- 정답 번호 + 한 줄 이유 -->
<div class="evi">          <!-- 지문 근거 / 선택지 대조, 2칸 -->
<div class="trap">         <!-- 보충 한 상자. 두 개 이상 넣지 않는다 -->
```

## 5. 내용과 문체 (가장 중요)

이 항목은 여러 차례 되돌린 끝에 정리된 것이다. **반드시 지킨다.**

### 5-1. 지문에서 답을 찾는 방식으로 쓴다

문제풀이 '일반론'을 쓰지 않는다. 대신 **몇 문단의 어떤 서술이 근거인지**를 밝힌다.

| 쓰지 말 것 | 이렇게 쓴다 |
|---|---|
| 풀이 논리 — 비교급을 먼저 사냥한다 | **①과 ④의 차이** · 2문단은 세 요인이 상호 작용한다고 서술했을 뿐 경중은 말하지 않았다. ①이 견준 내용은 같은 2문단에 근거 문장이 있다 |
| 대립 구도에서 '모두'는 경보음 | **고의설이 다룬 범위** · 3문단의 고의설 서술은 위법성의 인식이 고의의 요소라는 데까지다. 주의 의무와 정당한 이유는 4문단의 논점이다 |
| 과학 지문 첫 문항은 방향 뒤집기가 1순위 | **1문단이 정해 둔 것** · 신호는 수용체에서 생성되어 뇌로 전달되고, 맛 변화 물질은 수용체의 작동 방식을 바꾼다 |

선택지 소거 순서, 시간 단축 요령, '출제자의 수법' 같은 이야기는 수업 주제에서 벗어난다.

### 5-2. 답지 해설을 옮겨 적기만 하지 않는다

답지는 **근거 확인용**이다. 그것만 담을 것이면 강의할 이유가 없다.
지문의 어느 대목과 어느 대목을 이어야 답이 나오는지를 보여 준다.

### 5-3. 정보 과잉도 정보 부족만큼 문제다

분석을 덧붙일수록 좋아지지 않는다. 수업 주제에서 벗어날 만큼 많으면 주의가 분산된다.
**기준 파일의 밀도를 넘지 않는다.** 보충 상자는 슬라이드당 하나, 두세 문장까지.

### 5-4. AI가 만든 티가 나지 않게

- 과장된 소제목 금지: "이 표가 3문항을 다 푼다", "여기서 갈린다", "느낌상 ~ 노린다", "30초 문항이 된다"
- 소제목은 내용을 가리키는 이름으로 단다: `①과 ④의 차이`, `1문단의 인과`, `두 물질의 역할`
- 줄표(—) 남발, 과한 굵게·색 강조, 리듬을 맞춘 짧은 단정문을 피하고 평범한 서술문으로 쓴다
- 슬라이드 제목에 근거 문단을 밝히면 좋다: `민감도와 반응도 (4문단)`

### 5-5. 이미 배포한 자료는 손대지 않는다

개선 사항은 새로 만드는 자료에만 적용한다. 기존 파일에 일괄 적용하려면 먼저 물어본다.

## 6. CSS 규칙

### 6-1. 한국어 줄바꿈 (신규 덱 필수)

```css
body {
  word-break: keep-all;        /* 낱말 중간에서 끊기지 않게. "이해도 감 / 소" 방지 */
  overflow-wrap: break-word;   /* 컨테이너보다 긴 낱말의 안전장치 */
  text-wrap: pretty;           /* 마지막 줄에 한두 글자만 남는 것을 피한다 */
  letter-spacing: -0.015em;    /* 한 줄에 들어가는 글자를 늘려 넘침을 줄인다 */
}
```

네 가지를 모두 넣어도 남는 자리는 **문장을 몇 글자 줄여** 해결한다.
`keep-all`만으로는 "감소", "믿음", "경우"처럼 두 글자짜리 낱말이 혼자 남는 것을 막지 못한다.

### 6-2. 화면 위아래 잘림 방지

```css
.stage {
  width: min(100%, 1180px, (100vh - 8.5rem) * 16 / 9);
  aspect-ratio: 16 / 9;
}
```

`max-width: 1180px`만 주면 화면이 낮을 때 body의 세로 중앙 정렬 때문에
슬라이드 위아래가 **동시에** 잘린다(스크롤로도 볼 수 없다).

### 6-3. 슬라이드 밀도 조정

내용이 넘칠 때는 글자 크기를 일일이 손대지 말고 `:has()`로 슬라이드 종류별 규칙을 준다.

```css
.slide:has(.ans-banner) .trap p { font-size: 1.9cqw; line-height: 1.5; }
.slide:has(.two)  .card li      { font-size: 2cqw; }
.slide:has(.three) .card li     { font-size: 1.88cqw; }
```

모든 치수는 `cqw`(컨테이너 너비 비율) 기준이다. `px`를 쓰지 않는다.

## 7. 검증

`python -m http.server`로 띄우고 Playwright로 확인한다.
**Playwright는 토큰을 많이 쓰므로 `browser_evaluate` 한 번에 전부 검사한다.**
스크린샷은 정말 눈으로 봐야 할 때 한두 장만.

```js
// 4개 덱 × 3해상도를 한 번에: 내부 잘림 / 페이지 넘침 / 고아 행
async () => {
  const files = ['수능국어_3회_1-3번.html', '…'];
  const sizes = [[1920,1080],[1600,900],[1366,768]];
  const BLOCK = 'p,li,td,th,h1,h2,h3,.d,.t,.txt,.why,.src,.sub,.v,.k,.bogi';
  const out = {};
  for (const f of files) {
    const html = await (await fetch('수업/' + encodeURIComponent(f))).text();
    const rows = [];
    for (const [W,H] of sizes) {
      const ifr = document.createElement('iframe');
      ifr.style.cssText = `position:fixed;left:0;top:0;width:${W}px;height:${H}px;border:0;z-index:9999`;
      document.body.appendChild(ifr);
      ifr.srcdoc = html;
      await new Promise(r => ifr.onload = r);
      await new Promise(r => setTimeout(r, 220));
      const d = ifr.contentDocument;
      const slides = [...d.querySelectorAll('.slide')];
      const clipped = [], orphans = [];
      slides.forEach((s, si) => {
        slides.forEach(x => x.classList.remove('active'));
        s.classList.add('active');
        const ba = s.querySelector('.body-area');
        if (ba && ba.scrollHeight > ba.clientHeight + 2)
          clipped.push((si+1) + ':' + (ba.scrollHeight - ba.clientHeight));
        // 블록마다 글자를 Range로 훑어 줄별 글자 수를 센다
        s.querySelectorAll(BLOCK).forEach(el => {
          if (el.closest('svg') || el.querySelector(BLOCK)) return;
          const lines = new Map(), r = d.createRange();
          const w = d.createTreeWalker(el, NodeFilter.SHOW_TEXT);
          let n;
          while ((n = w.nextNode())) {
            const p = n.parentElement;
            if (p.classList.contains('ans-chip') || p.classList.contains('tag')) continue;
            for (let i = 0; i < n.nodeValue.length; i++) {
              const c = n.nodeValue[i];
              if (!c.trim()) continue;
              r.setStart(n, i); r.setEnd(n, i + 1);
              const rc = r.getBoundingClientRect();
              if (!rc.width && !rc.height) continue;
              const key = Math.round(rc.top / 2) * 2;
              lines.set(key, (lines.get(key) || '') + c);
            }
          }
          const arr = [...lines.entries()].sort((a,b) => a[0]-b[0]).map(e => e[1]);
          if (arr.length < 2) return;
          arr.forEach(l => { if (l.length <= 3) orphans.push(`${si+1}장 "${l}"`); });
        });
      });
      rows.push(`${W}x${H} 잘림[${clipped.join(',')||'-'}] 고아[${orphans.join(';')||'-'}] `
              + `넘침${Math.max(0, d.documentElement.scrollHeight - H)}`);
      ifr.remove();
    }
    out[f] = rows;
  }
  return JSON.stringify(out, null, 1);
}
```

**통과 기준: 세 항목 모두 0.**

- `잘림` — `.body-area` 안에서 내용이 잘림. 해당 슬라이드 내용을 덜거나 `:has()` 규칙으로 압축
- `넘침` — 슬라이드가 화면을 벗어남. 6-2의 `.stage` 규칙 확인
- `고아` — 세 글자 이하로 끝나는 행. 6-1을 확인하고, 그래도 남으면 문장을 줄인다
