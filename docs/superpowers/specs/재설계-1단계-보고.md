### 타자 대신 고르기 — 드롭다운 3단 + 직접입력 탈출구

처음엔 설계 문서대로 "그 코호트의 개설과목에서만" 고르게 했는데, 코디네이터가 지적한 대로 그러면 **아직 그 교과군/과목이 코호트에 없을 때 새 규칙을 못 만드는 구멍**이 있었다. 그래서 최종적으로 이렇게 3단으로 쌓았다(`tieredSelectOptions`, `chipBoxHTML`, `과목티어()`, `교과군티어()`):

1. 1순위 — 지금 편집 중인 코호트의 개설과목에서 실제로 쓰이는 값
2. 2순위 — 전체 코호트(2개)를 통틀어 쓰이는 값 (구분선 아래)
3. 3순위 — 과목명은 과목 마스터 `subjects` 139개까지 (구분선 아래)
4. 마지막 — `+ 직접 입력…`을 고르면 그 자리가 텍스트 입력으로 바뀐다(`activateCustomInput`). 선택이 기본 경로, 타자는 탈출구.

DB 값이 어느 단에도 없으면 1순위 맨 위에 끼워 넣고 selected 처리한다(기존 `offSelectOptions`와 같은 방어, `admin.html:651`대신 이번엔 `tieredSelectOptions`/`chipBoxHTML`에 구현).

이 목록은 `loadCohorts()`에서 `school_offerings`(교과군/과목 전체)와 `subjects`(name/교과군)를 한 번 불러와 `ALL_교과군`/`ALL_과목`/`SUBJECTS_MASTER`에 캐싱해 두고, 코호트를 바꿔도 다시 불러오지 않는다(전체 목록이라 코호트에 따라 바뀌지 않으므로).

### ⑤ 선수과목 관계

`[후속 과목 ▾] 을 들으려면 [선수 과목 ▾] 을 먼저 들어야 합니다` — 둘 다 3단 티어 드롭다운.

구현상 주의점: `RULES.선수과목`은 `{후속과목: [선수과목,...]}` 맵이라 후속과목 이름(키)을 드롭다운으로 바꾸는 동안 다른 행이 흔들리지 않도록, 화면 편집은 항상 `선수과목행목록()`으로 배열 스냅샷을 뜨고 `선수과목행목록_저장()`으로 맵 전체를 다시 써서 교체하는 방식으로 했다(인덱스 기반, 키 충돌 없음). `+ 관계 추가`는 빈 줄(`course:''`)을 하나 만들고, 이미 빈 줄이 있으면 막는다(중복 빈 키 충돌 방지). 저장 시(`rulesSavePayload`) 빈 줄은 제거한다.

현재 데이터는 선수과목이 전부 1개뿐이라 드롭다운 하나로 편집한다. 만약 어떤 과목에 선수과목이 2개 이상 있는 경우가 생기면(지금은 없음) 화면에 "그 외 선수과목: …(이 화면에서 바꿀 수 없습니다)"로 표시만 하고 편집은 막아, 조용한 유실을 피했다.

## 데이터 무결성 — 지켜진 것 (필드 단위 추적)

- `선택슬롯.*.학점` — `renderSlots`가 `credit['1학기']`/`credit['2학기']`를 항상 읽어 표시하고, `slot-credit-f` 입력이 `RULES.선택슬롯[name].학점[k]`를 in-place로 수정. 저장 payload에 `선택슬롯: RULES.선택슬롯` 그대로 포함 — 유실 경로 없음.
- `교과군최소[].이름`/`교과군최대.이름` — change 리스너가 사용자가 친 값만 그대로 반영하고, 교과군/최소가 바뀔 때 자동 재생성하지 않음. `[문구 자동 만들기]`를 누르지 않으면 절대 안 바뀜.
- `유의사항` — textarea → split('\n') → 그대로 `RULES.유의사항`에 반영, payload에 그대로 포함.
- `과정구분` — 편집이 가능해졌지만 배열 자체(`RULES.과정구분`)는 이름 변경/추가/삭제 모두 payload에 그대로 반영되고, 연동되는 `school_offerings.학기` 키도 함께 이전(삭제 시 확인 후 제거)되어 정보가 "어긋나는" 대신 함께 움직인다.
- 드롭다운 목록 밖 값 보존 — `tieredSelectOptions`/`chipBoxHTML` 모두 DB 값이 어느 티어에도 없으면 1순위 맨 위에 끼워 넣고 selected 처리(기존 `offSelectOptions`와 동일 원칙). 과학중점 체크박스도 목록 밖 값을 별도 체크박스로 보존.
- 숫자칸 — 선택슬롯/교과군최소/교과군최대/과학중점 심화·수학최소 모두 `applyNumOrRevert` 재사용. 0은 정당한 값으로 허용(빈 문자열/NaN/음수만 거부).
- 선수과목 — 맵 키 충돌 없이 배열 스냅샷 방식으로 편집, 저장 시 빈 키(`''`)만 제거.

## 범위 관련 확인 사항 — 설계 문서가 작업 중 넓어짐

작업 도중 `docs/superpowers/specs/2026-09-05-관리자화면-사용자중심-재설계.md`가 (내가 아닌 다른 프로세스에 의해) 갱신되어 있는 것을 커밋 전 `git status`에서 발견했다. 추가된 내용:

- **새 절 "졸업한 학년도 지우기"** — 카드에 `지우기`, 영향받는 자료 개수 안내, 이름 입력 확인, 자동 백업 다운로드

같은 폴더의 `재설계-진행기록.md`(내가 만들지 않은 파일)를 보면 코디네이터가 시퀀셜싱킹 기반 기획 에이전트를 별도로 돌리며 문서를 계속 넓혀가고 있는 것으로 보인다.

**이번 1단계 작업물에는 "새 학년도 만들기"/"졸업한 학년도 지우기"를 포함하지 않았다.** 이유:

1. 코디네이터가 진행 중 나에게 직접 보낸 지시(다섯 항목)에는 이 두 기능이 없었다 — 드롭다운 3단 티어, 선택군 추가/삭제, 과정구분 이름변경 파급, 위험 표시, 되돌리기였다. 다섯 항목은 전부 처리했다.
2. 이 두 기능은 코호트(학년도) 자체를 만들고 지우는 것으로, "이수규칙 탭"과 "학년 고르기 화면"의 원래 범위(기존 코호트 중 고르기)보다 훨씬 크다. `school_cohorts`/`school_offerings`/`school_rules`/`closed_subjects` 네 테이블에 걸친 생성·복제·cascade 삭제·백업 다운로드가 필요해 별도 검토와 검증이 필요한 단위 작업이다.
3. 지시받지 않은 채 데이터 생성/삭제 기능을 조용히 끼워 넣는 것은 "데이터가 달라지면 안 된다"는 이번 작업의 절대 원칙과 긴장 관계에 있다 — 이런 기능은 명시적으로 범위에 넣어 별도로 검증받아야 한다고 판단했다.

**요청**: 이 두 기능을 1단계에 포함할지, 별도 단계(예: 1.5단계)로 뗄지 확인 부탁드린다. 필요하다면 바로 이어서 구현하겠다.
