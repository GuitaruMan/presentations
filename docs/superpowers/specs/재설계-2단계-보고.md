## 1. 학교 교육과정 탭

### 1-1. 열 순서 재배치

지시대로 `과목명 | 교과군 | 유형 | 학점 | 학년 | 선택군 | 학기 | 성적방식 | 수능 출제 | 삭제`로 바꿨다(`admin.html` 363~374행 thead, 1276~1287행 `offRowHTML`). 학기 칸은 `.sem-box`(옅은 테두리 + 회색 배경, 198행 CSS)로 감싸 한 덩어리로 보이게 했고, 수능 칸에는 왼쪽 세로 구분선(`.exam-col-th`/`td.exam-col`, 200행)을 넣었다. 헤더는 `수능` → `수능 출제`로 바꿨다.

### 1-2. 정렬

헤더(`<th data-sort="...">`)를 누르면 그 필드로 정렬한다. 과목명·교과군·유형·성적방식·선택군은 `localeCompare(..., 'ko')`, 학점·학년은 수치 비교(`renderOfferings` 내 정렬 콜백, 1213~1223행). 누를 때마다 `offSortDir`을 토글하고 화살표(▲▼)를 헤더에 붙인다. 기본은 `offSortKey = null`(원래 순서 = DB id 순, `D.school.개설`가 `select('*')`로 읽어온 순서를 그대로 씀)이고, `원래 순서로` 버튼(`#offSortResetBtn`)으로 되돌릴 수 있다.

### 1-3. 필터

교과군·선택군·학년 드롭다운 3개를 검색창 옆에 두었다(`#offFilterGroup`/`#offFilterTrack`/`#offFilterGrade`). `offRefreshFilterOptions()`가 매 렌더마다 지금 코호트의 실제 값으로 옵션을 다시 채운다(선택된 값은 유지). 필터/검색이 하나라도 걸리면 카운트 표시가 "106개 중 32개 보는 중" 형식으로 바뀌고, 안 걸리면 기존처럼 "32과목 (전체 106)"으로 표시한다(`renderOfferings`, 1179~1211행).

### 1-4. 과목명·선택군을 드롭다운으로

1단계의 3단 티어 패턴을 그대로 재사용했다. 다만 이수규칙 탭이 쓰던 `SCHOOL`(선택군 `'지정'`을 걸러낸 목록)은 이 탭에 안 맞아서(관리자는 `'지정'` 과목도 전체 편집해야 함) `D.school.개설`(미필터 전체) 기준의 별도 티어 함수를 새로 만들었다.

- `개설과목명티어()` — 1순위: 이 코호트 개설과목 전체(`D.school.개설`), 2순위: 전체 코호트(`ALL_과목`), 3순위: 과목 마스터(`SUBJECTS_MASTER`, 139개).
- `개설선택군티어()` — 1순위: 이 코호트 개설과목에서 실제 쓰는 선택군, 2순위: 전체 코호트(`ALL_선택군`, 새로 추가).
- 둘 다 `tieredSelectOptions()`로 렌더하고 마지막에 `+ 직접 입력…`(`CUSTOM_VALUE`)을 붙인다. 골랐을 때 `activateCustomInput()`으로 그 자리를 텍스트칸으로 바꾼다(1단계와 동일 탈출구).
- `ALL_선택군`은 1단계에 없던 값이라 `loadCohorts()`의 `school_offerings` 조회에 `선택군` 컬럼을 추가해 함께 모았다(707행 select문, 719~725행 집계).

**목록 밖 DB 값 보존**: `tieredSelectOptions()`는 값이 어느 티어에도 없으면 1순위 맨 위에 끼워 넣고 selected 처리한다(1단계와 동일 방어, 새로 만든 게 아니라 그대로 호출). `offSelectOptions()`(교과군/유형/성적방식)는 손대지 않았다.

### 새 과목 추가 — 과목명 기본값을 비움

`+ 새 과목 추가`가 만들던 기본값 `과목:'새 과목'`을 `과목:''`로 바꿔, 관리자가 드롭다운에서 직접 고르게 했다(1057~1064행). `saveOffering()`에 새 행(`!row.id`)이면서 과목명이 비어 있으면 저장을 막는 가드를 추가했고(1291행), 저장된 과목명이 과목 마스터(139개)에 없으면 "저장됨 (과목 마스터에 없는 이름입니다)" 경고를 `offSt`에 띄운다(1302~1306행, 저장은 그대로 진행 — 직접 입력 탈출구를 막지 않기 위해).

## 2. 새 학년도 만들기 / 졸업한 학년도 지우기

### 2-1. 학년 고르기 화면 카드 확장

`renderCohortCards()`(818~855행)로 새로 만들었다. 카드마다:

- 과목 수(`과목 N개`) — `loadCohorts()`가 `school_offerings`를 코호트 구분 없이 한 번에 불러와(`cohort_id` 포함) `countByCohort`로 집계한다(추가 쿼리 없음, 기존 2순위/3순위 드롭다운 준비 쿼리를 재사용).
- `학생 화면에 보이기` 스위치(`.expose-sw`, 토글 CSS 신설) — 누르면 `toggleCohortExposure()`가 `school_cohorts.노출`을 바로 update하고, 성공하면 그 카드의 `지우기` 버튼 잠금 상태를 함께 갱신한다.
- `지우기` 버튼 — 노출 중이면 `disabled` + 툴팁("학생 화면에 보이는 동안에는 지울 수 없습니다. 먼저 보이기를 꺼 주세요.").
- 맨 끝에 `+ 새 학년도 만들기` 카드(점선 테두리 버튼).

카드 클릭 영역(제목/설명, `.cohort-card-pick`)과 스위치/지우기 버튼은 분리했고, 스위치·지우기 클릭에는 `stopPropagation()`을 걸어 진입 클릭으로 번지지 않게 했다.

### 2-2. 새 학년도 만들기

`openNewCohortModal()`/`$('#ncCreateBtn').onclick`(886~982행)로 구현했다. 입력: 입학연도(숫자 검증)·화면 표시 이름·학생 안내문·대상·본뜰 학년도(드롭다운, 기존 코호트 목록).

동작 순서(지시받은 그대로):
1. `makeCohortId()`가 `{입학연도}-g2`를 만들고, 이미 있으면 `-2`, `-3`… 을 붙여 중복을 피한다.
2. `school_cohorts`에 새 행 insert, `노출: false`로 시작.
3. 본뜰 코호트의 `school_offerings` 전체을 읽어 `id`만 제거하고 `cohort_id`를 새 코호트로 바꿔 그대로 insert.
4. 본뜰 코호트의 `school_rules` 1행을 같은 방식으로 복사.
5. `closed_subjects`는 복사하지 않음(코드에 아예 손대지 않았다 — 지시대로).
6. 성공하면 모달을 닫고 `loadCohorts()`로 카드 목록을 새로 불러온 뒤, 목록에 새 코호트가 나타나는 것을 짧게 폴링(최대 4초)해 `selectCohort()`로 바로 진입한다.

### 2-3. 학년도 지우기 — 안전장치 네 겹

`openDeleteCohortModal()`/`$('#dcConfirmBtn').onclick`(989~1085행).

1. **노출 중이면 버튼이 잠김** — `renderCohortCards()`에서 이미 `disabled` 처리, 클릭 핸들러도 `if(!b.disabled)`로 한 번 더 막는다.
2. **무엇이 사라지는지 숫자로** — 모달을 열면 `school_offerings`/`school_rules`/`closed_subjects` 세 테이블을 `count:'exact', head:true`로 실제로 세어(row body 없이 개수만) "개설과목 N개 / 이수규칙 1벌 / 개설현황(폐강 표시) N개"를 보여준다.
3. **이름을 직접 입력해야 활성화** — 텍스트칸에 학년도 제목을 정확히 쳐야(`input` 이벤트로 매번 비교) `백업 내려받고 지우기` 버튼이 풀린다.
4. **삭제 직전 자동 백업, 다운로드 후 삭제** — `school_cohorts`(1행) + `school_offerings` 전체 + `school_rules` + `closed_subjects`를 JSON 하나로 묶어 Blob 다운로드(`{제목}-백업-{YYYYMMDD}.json`). 다운로드 트리거 후 800ms 기다렸다가(`URL.revokeObjectURL`을 늦춰 다운로드가 끝날 시간을 줌) 그제서야 `school_cohorts` delete를 실행한다.

삭제는 `school_cohorts` 행 하나만 지우면 되고, FK `on delete cascade`(`docs/superpowers/plans/2026-09-01-2028과목선택-db이원화.md` 102/117/128행에서 확인)로 `school_offerings`/`school_rules`/`closed_subjects`가 함께 지워진다. 되살리기 기능은 지시대로 만들지 않았다.

## 지켜진 것 — 데이터 무결성

- 학교 교육과정 탭 편집 필드(과목/교과군/유형/운영학점/선택군/학년/평가/수능/학기)는 손대지 않았다 — 열 순서와 입력 위젯(과목/선택군만 텍스트→드롭다운)만 바꿨다. `saveOffering()`의 payload 조립 로직은 그대로다.
- `학기` JSONB 편집 로직(`off-sem-f` 체크박스, `학기체크박스HTML`)은 내용을 바꾸지 않고 `.sem-box`로 감싸기만 했다.
- `평가` null 보존, 드롭다운 목록 밖 값 보존(`offSelectOptions`/`tieredSelectOptions` 모두 기존 방어 그대로) — 새로 추가한 과목명/선택군 드롭다운도 동일 원칙 적용.
- 3단계(생성/삭제)는 설계상 데이터가 바뀌는 것이 목적이므로 예외로 뒀고, 그 안에서도 기존 코호트(1, 3)의 행은 절대 건드리지 않는다 — 생성은 새 행만 insert, 삭제는 삭제 대상 코호트의 `cohort_id`로만 필터링된 행만 지운다.

### 2. 왕복 무결성 — `school_offerings` 182행(코호트 1: 106, 코호트 3: 76)

`.env`(`E:\ForClaude\Create\ForCir_data\.claude\worktrees\db-migration\.env`)로 Python(`supabase`, `python-dotenv`) 사용. `saveOffering()`의 payload 조립 로직을 그대로 재현해 두 코호트의 개설과목 전체를 **편집 없이** update → 재조회 → deep-equal:

```json
{
  "1": { "row_count": 106, "deep_equal_after_save": true },
  "3": { "row_count": 76, "deep_equal_after_save": true }
}
```

이후 작업 시작 시점 스냅샷과 현재 DB를 다시 비교(복원 확인):

```json

  "3": { "matches_original": true, "row_count": 76 }
}
```

두 코호트 모두 편집 없는 저장 후 원본과 완전히 같았다.

### 3. 3단계 기능 테스트 — 실제 생성·삭제

기존 코호트 1(`2026-g2`)을 본떠 테스트 학년도(`입학연도: 9999`, `코호트id: "9999-g2"`)를 실제로 만들고, 확인 후 지웠다. `admin.html`의 생성/삭제 로직(insert → 복사 → cascade delete)을 Python으로 그대로 재현했다(`makeCohortId`/`ncCreateBtn`/`dcConfirmBtn` 핸들러와 동일한 순서·필드).

```json

  "created_exposure_false": true,
  "source_offerings_count": 106,
  "new_offerings_count": 106,
```

**삭제(cascade) 결과**:
```json
{
  "before_offerings": 106,
  "before_rules": 1,
  "after_offerings_should_be_0": 0,
  "after_rules_should_be_0": 0,
```

**원상복구 확인**: 테스트 후 기존 코호트 1(106개)·3(76개)의 개설과목 수와 `school_cohorts`에 남은 코호트id(`2026-g2`, `2025-g3` 두 개뿐)를 재확인해, 기존 데이터가 전혀 건드려지지 않았음을 확인했다.

2. **선택군 티어(`ALL_선택군`)를 이번에 새로 추가**했다. 1단계의 `ALL_교과군`/`ALL_과목`과 같은 방식이지만, `loadCohorts()`의 `school_offerings` 조회 컬럼을 늘렸으므로(교과군,과목 → 교과군,과목,선택군) 데이터량이 아주 약간 늘었다(성능에 영향 없는 수준, 코호트 2개 총 182행).
3. **`+ 새 학년도 만들기`로 만든 코호트에 자동 진입하는 로직**은 `loadCohorts()`가 비동기라 최대 4초 폴링으로 기다린다. 네트워크가 느리면 자동 진입에 실패하고 카드 화면에 머물 수 있는데, 이 경우도 새로 만든 카드가 목록에 보이므로 관리자가 직접 눌러 들어가면 된다(치명적이지 않음).
4. **테스트 학년도(`9999-g2`)는 이번 검증 과정에서 실제로 생성 후 삭제까지 완료**했다. 삭제가 cascade로 완전히 처리됐음을 재조회로 확인했고, `school_cohorts`에 남은 것은 원래의 두 코호트(`2026-g2`, `2025-g3`)뿐이다.
